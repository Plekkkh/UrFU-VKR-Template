\chapter{Решение прикладных задач в рамках проекта}

После успешного развертывания инфраструктуры и настройки процессов совместной разработки, фокус был смещен на решение исследовательских и инженерных задач, описанных в индивидуальном задании: устранение архитектурных ограничений модуля ИИ-агента и разработка матрицы кибератак.

\section{Адаптация модуля классификации для работы с различными LLM}

В исходном прототипе системы модуль ИИ-агента (\code{LLMClassifier}), отвечающий за первичный анализ алертов и категоризацию инцидентов, имел жесткую архитектурную привязку к провайдеру Anthropic.
Изначально использовался специфичный класс \code{ChatAnthropic}.
Это создавало риски Vendor Lock-in, ограничивало гибкость системы и делало невозможным тестирование системы в закрытом контуре без доступа к интернету.

В рамках задачи мною был проведен глубокий рефакторинг класса \code{LLMClassifier} и связанных модулей для обеспечения поддержки различных LLM-провайдеров.

\textbf{Ключевые архитектурные изменения:}

\begin{enumerate}
    \item Осуществлен переход на универсальное подключение к LLM на базе фабрики \code{init\_chat\_model} из фреймворка LangChain.
    Дефолтным провайдером назначен \code{openai}, что обеспечивает совместимость с большинством современных облачных API-маршрутизаторов, например, OpenRouter и локальных серверов: Ollama, vLLM\@.
    \item Управление провайдером вынесено в переменные окружения.
    Переключение моделей теперь осуществляется бесшовно через параметры \code{LLM\_BASE\_URL}, \code{LLM\_PROVIDER} и \code{LLM\_MODEL} в файле \code{.env}.
    \item Реализована динамическая проверка наличия ключей доступа (\code{LLM\_API\_KEY}) в зависимости от выбранного провайдера.
    При использовании локального \code{LLM\_BASE\_URL} агент способен функционировать без API-ключа.
    \item Файл \code{pyproject.toml} актуализирован: добавлены пакеты \code{python-dotenv}, \code{langchain} и \code{langchain-openai}.
\end{enumerate}

Для проверки внесенных изменений были обновлены юнит-тесты в файлах \code{tests/test\_llm\_classifier.py} и \code{tests/test\_hitl.py}.
Кроме того, было проведено функциональное тестирование с использованием открытой языковой модели \code{nvidia/nemotron-3-nano-30b-a3b:free}.

В ходе живых тестов выявлены следующие аналитические особенности поведения LLM:
\begin{itemize}
    \item При классификации фишинговых атак модель проявляет избыточную детализацию, указывая подтехнику MITRE ATT\&CK (например, \code{T1566.002}) вместо требуемой родительской техники (\code{T1566}), что требует доработки системы валидации вывода.
    \item При анализе алертов, связанных с вредоносным ПО (Malware), модель занижает уровень угрозы до «High» вместо ожидаемого «Critical».
\end{itemize}
Эти наблюдения зафиксированы для дальнейшей калибровки системных промптов.

\section{Разработка сценариев кибератак для тестирования системы}

Для отладки ИИ-агентов и проверки автоматизированных сценариев реагирования через плейбуки CACAO 2.0, на стенде необходима реалистичная телеметрия.
С этой целью мною был разработан документ, описывающий сценарии эмуляции атак, охватывающий различные векторы проникновения и закрепления в инфраструктуре.

\subsection{Сценарий 1: Пробой периметра}

\textbf{Цель:} Получение несанкционированного доступа к файлу ограниченного доступа на внутреннем файловом сервере (\code{FS-01}).\\
\textbf{Вектор атаки:} \code{ITDR-02} (External) $\rightarrow$ \code{WEB-01} (DMZ, Linux) $\rightarrow$ \code{FS-01} (LAN, Windows).

\textbf{Цепочка атаки:}
\begin{enumerate}
    \item Злоумышленник эксплуатирует уязвимость в веб-приложении на сервере \code{WEB-01}, инициирует Reverse Shell и получает доступ в контексте пользователя \code{www-data}.
    \item Используя полученные привилегии, нарушитель проводит локальную разведку.
    Атакующий извлекает из переменных окружения приложения доменные учетные данные сервисного аккаунта, которые веб-сервис использует для обращения к файловому серверу.
    \item Злоумышленник разворачивает на \code{WEB-01} SOCKS Proxy, чтобы туннелировать трафик к файловому серверу.
    \item Используя полученные учетные данные, злоумышленник подключается к \code{FS-01} по протоколу SMB и получает несанкционированный доступ к целевому файлу.
\end{enumerate}

\subsection{Сценарий 2: Полная компрометация домена}

\textbf{Цель:} Извлечение базы данных Active Directory --- \code{ntds.dit}.\\
\textbf{Вектор атаки:} \code{ITDR-01} (LAN) $\rightarrow$ \code{RDP-01} (LAN, Windows Server) $\rightarrow$ \code{DC-01} (LAN, Active Directory).

\textbf{Цепочка атаки:}
\begin{enumerate}
    \item С узла внутреннего нарушителя \code{ITDR-01}, используя права рядового пользователя, проводится атака \textit{AS-REP Roasting}.
    Контроллер домена отдает зашифрованный билет, который атакующий брутфорсит и получает пароль.
    \item Атакующий подключается к \code{RDP-01} по протоколу WinRM, используя полученные учетные данные.
    Обнаружив у себя право \code{SeBackupPrivilege}, он создает теневые копии веток реестра для извлечения NTLM-хэша локального администратора.
    \item Поскольку узел \code{RDP-01} имеет настроенное неограниченное делегирование, любой аутентифицированный субъект оставляет в памяти свой TGT-билет.
    Атакующий принуждает контроллер домена подключиться к \code{RDP-01} и перехватывает TGT-билет машинной учетной записи.
    \item Конвертируя TGT-билет в формат \code{.ccache}, злоумышленник использует его для аутентификации на \code{DC-01} и реализует атаку \textit{DCSync}, выгружая базу данных домена.
\end{enumerate}

\subsection{Сценарий 3: Отказ в обслуживании почтового сервера}

\textbf{Цель:} Скрытое проникновение, перехват учетных данных администратора через троянизированное ПО и вывод из строя почтового шлюза.\\
\textbf{Вектор атаки:} \code{ITDR-02} (External) $\rightarrow$ \code{PC-01} (LAN, Windows) $\rightarrow$ \code{RDP-01} (LAN) $\rightarrow$ \code{MAIL-01} (DMZ, Linux).

\textbf{Цепочка атаки:}
\begin{enumerate}
    \item Злоумышленник отправляет целевое фишинговое письмо рядовому сотруднику с вредоносным вложением \code{index.docm}.
    \item При открытии документа скрытый макрос инициирует скачивание и запуск PowerShell-скрипта напрямую в оперативную память, устанавливая Reverse Shell.
    \item Закрепившись на рабочей станции \code{PC-01}, злоумышленник размещает на внутреннем файловом сервере специально подготовленный архив, эксплуатирующий уязвимость CVE-2023-38831.
    \item Системный администратор с сервера \code{RDP-01} открывает данный архив.
    Эксплойт незаметно устанавливает в систему администратора троянизированный RAT-клиент PuTTY\@.
    При следующей легитимной попытке администратора подключиться к \code{MAIL-01}, троян перехватывает учетные данные и передает их злоумышленнику.
    \item Атакующий использует перехваченные данные для подключения к \code{MAIL-01}.
    Для получения прав \code{root} эксплуатируется уязвимость Copy Fail --- CVE-2026-31431.
    \item Получив максимальные привилегии, злоумышленник принудительно останавливает службу почтового сервера, реализуя отказ в обслуживании.
\end{enumerate}

Разработанные сценарии утверждены в качестве эталонной базы для написания автоматизированных PoC-скриптов и генерации качественной телеметрии для отладки ИИ-агентов.
