\chapter{Ход выполнения работы}

\section{Заполнение базы данных}

Для проверки работоспособности ограничений целостности и подготовки данных к экспорту разработан скрипт \code{1\_insert\_data.sql}.
В каждую из 10 таблиц добавлено по 5 кортежей.
Соблюдены правила каскадной очередности: сначала заполнены родительские таблицы, затем --- дочерние и связующие таблицы.

\section{Подготовка и экспорт данных базы в документы пользователя}

Для экспорта был выполнен скрипт \code{2\_pre\_export\_check.sql}:
\begin{enumerate}
    \item Назначение администратора (владельца) базы данных c помощью инструкции \code{ALTER AUTHORIZATION ON DATABASE::pub\_house\_db TO sa;}
    \item Принудительное закрытие всех активных пользовательских соединений и перевод БД в однопользовательский режим для эксклюзивного доступа администратора командой \code{ALTER DATABASE} \code{pub\_house\_db SET SINGLE\_USER WITH ROLLBACK IMMEDIATE;}
    \item Проверка логической и физической целостности всех объектов БД с помощью команды \code{DBCC CHECKDB (N'pub\_house\_db');}
    \item Возврат БД в многопользовательский режим для работы утилит экспорта командой \code{ALTER DATABASE pub\_house\_db SET MULTI\_USER;}
\end{enumerate}

Средствами мастера Generate Scripts в SSMS был создан транзакционный скрипт \code{export\_data.sql}, содержащий \code{SET IDENTITY\_INSERT ON} и команды \code{INSERT} для всех таблиц.
С помощью консольной утилиты \code{bcp} все данные таблицы \code{Books} были выгружены в пользовательский текстовый документ \code{books\_export.txt}.

\section{Импорт данных из документов пользователя в базу данных}

Для проверки процедуры восстановления данных был выполнен подготовительный скрипт \code{3\_prepare\_import.sql}, закрывающий все активные соединения с БД и очищающий данные перед тестированием импорта с учетом порядка внешних ключей.

Через утилиту командной строки \code{sqlcmd} с ключами \code{-S}, \code{-E}, \code{-i export\_data.sql} и \code{-o import\_log.txt} был выполнен пакетный импорт данных из пользовательского скрипта.
Весь ход выполнения зафиксирован в файле лога \code{import\_log.txt}.

Выполнена пост-импортная проверка целостности базовых таблиц, внешних ключей и проверочных ограничений командой \code{DBCC CHECKDB}, которая подтвердила полное сохранение логической и физической целостности данных.

\section{Настройка автоматизации обслуживания базы данных}

Поскольку в редакции Microsoft SQL Server Express отсутствует планировщик заданий SQL Server Agent, автоматизация регламентного обслуживания реализована посредством связки T-SQL скрипта \code{auto\_maintenance.sql} и утилиты \code{sqlcmd} и системного Windows Task Scheduler.

В скрипте \code{auto\_maintenance.sql} выстроен строго детерминированный порядок выполнения задач автоматизации:
\begin{enumerate}
    \item Автоматическая проверка целостности БД, которая выполняется первой, чтобы гарантировать, что последующая оптимизация и резервное копирование не будут производиться над поврежденной структурой.
    \item Оптимизация таблиц, перестроение индексов и обновление статистики для устранения фрагментации таблиц и избыточности индексных страниц, а также актуализация статистики оптимизатора запросов.
    \item Автоматическое полное резервное копирование базы данных в файл с динамической меткой даты в имени.
\end{enumerate}

В Планировщике заданий Windows создана задача с ежедневным триггером расписания, вызывающая \code{sqlcmd} для исполнения скрипта \code{auto\_maintenance.sql} в фоновом режиме.
