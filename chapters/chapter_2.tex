\section{Реализация сценариев доступа и создание учетных записей}

\subsection{Настройка механизма регистрации и входа}

Поскольку по умолчанию экземпляр SQL Server Express использует только аутентификацию Windows, в свойствах сервера был активирован смешанный режим проверки подлинности --- SQL Server and Windows Authentication mode (рисунок~\ref{fig:switching_to_mixed_authentication_mode}), после чего служба СУБД перезапущена.
Это позволило создавать независимые учетные записи SQL Server с парольной защитой и контролем политик сложности пароля (\code{CHECK\_POLICY = ON}).

\subsection{Создание учетных записей и разграничение прав}

Созданы серверные имена входа (\code{LOGIN}) и сопоставленные с ними пользователи базы данных (\code{USER}) для двух администраторов и двух сотрудников издательства.

Учетные записи администраторов были включены в привилегированную роль \code{db\_owner}, которая наделяет их полными правами управления БД.

Для реализации принципа наименьших привилегий созданы ролевые группы для менеджеров и редакторов.
С помощью инструкций \code{GRANT SELECT}, \code{INSERT}, \code{UPDATE} и \code{DENY} права доступа строго разграничены в соответствии с матрицей доступа: менеджеру предоставлен доступ к контуру заказов и контрактов, а редактору --- к контуру подготовки книг и работы с авторами.

Корректность регистрации пользователей и привязки ролей проверена запросом к системным каталогам \code{sys.database\_principals} и \code{sys.database\_role\_members} (рисунок~\ref{fig:created_users_check}).

Соотвествующие листинги SQL-команд приведены на рисунках~\ref{fig:access_control1} и~\ref{fig:access_control2}.

Для верификации корректности авторизации выполнен скрипт \code{2\_test\_accounts.sql} (рисунок~\ref{fig:test_accounts}), а так же проведены прямые подключения к СУБД в среде SSMS под созданными УЗ (рисунок~\ref{fig:user_manager_login}).

\section{Настройка сбора журналов безопасности и мониторинг подключений}

\begin{enumerate}
    \item В параметрах безопасности сервера установлен режим \textit{Both failed and successful logins} (рисунок~\ref{fig:login_auditing}), обеспечивающий запись всех попыток аутентификации в журнал сервера.
    \item Создан и активирован серверный аудит, направляющий бинарные журналы событий безопасности \code{.sqlaudit} в директорию \code{C:\\pub\_db\_work\\} (рисунок~\ref{fig:audit_check}).
    \item Создана серверная спецификация аудита, отслеживающая группы событий \code{FAILED\_LOGIN\_GROUP} и \code{SUCCESSFUL\_LOGIN\_GROUP}.
    \item Создана спецификация аудита на уровне БД \code{pub\_house\_db}, регистрирующая изменения схемы, прав доступа и обращения пользователей к защищаемым таблицам.
    \item Реализован SQL-запрос к динамическим административным представлениям \code{sys.dm\_exec\_sessions} и \code{sys.dm\_exec\_connections} (рисунок~\ref{fig:connection_monitoring}), позволяющий в реальном времени выводить список всех активных сессий, логин, сетевой адрес, клиентское приложение, время входа и статус сессии (рисунок~\ref{fig:connections_check}). Параллельно проведена визуальная инспекция пула подключений через графический инструмент Activity Monitor в SSMS (рисунок~\ref{fig:activity_monitor}).
\end{enumerate}

Листинг команд представлен на рисунке~\ref{fig:security_audit_setup}.

\section{Детектирование подозрительных событий и имитация атак}

Выполнена серия последовательных подключений с неверным паролем для одного из пользователей БД, имитируя брутфорс-атаку.
Каждая неудачная попытка сопровождалась отказом входа с ошибкой (рисунок~\ref{fig:failed_logins_imitation})

С помощью табличной функции \code{sys.fn\_get\_audit\_file} выполнена выгрузка детального журнала аудита (рисунок~\ref{fig:verifying_audit_logs}), где зафиксированы все события по их типам, коды действий, имена субъектов, текст перехваченных T-SQL инструкций и время.

Выполнен аналитический запрос детектирования аномалий (рисунок~\ref{fig:detection_analysis}), агрегирующий несанкционированные обращения и многократные ошибки аутентификации по конкретным учетным записям, что позволило однозначно выявить логин нарушителя и период атаки.
